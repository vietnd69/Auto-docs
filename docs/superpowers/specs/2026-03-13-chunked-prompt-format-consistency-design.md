# Design: Chunked Prompt Format Consistency

**Date:** 2026-03-13
**Status:** Draft
**Scope:** `chunked_prompt.py` only

---

## Problem

Files generated by the chunked pipeline (`build_merge_prompt`) produce inconsistent Markdown format compared to the project standard exemplified by `consolecommands.md` (generated by `prompt.py`).

Three concrete issues:

| # | Issue | Root cause |
|---|-------|------------|
| 1 | `tags: ["CLASSIFIED", "ITEMMIMIC", ...]` — extra quotes in YAML | Line `tags_yaml = ", ".join(f'"{t}"' for t in presynthesis.tags)` wraps each value in double quotes |
| 2 | `## Main functions` uses wrong body style — section headers instead of bullets | Task 5 in `build_merge_prompt()` says "format as ### headings" but omits exact syntax (`### \`Name(params)\``), bullet character (`*`), field ordering, and whether `**Error states:**` exists |
| 3 | `## Dependencies & tags` has inconsistent labels | Task 7 and the corresponding template body placeholder (`<FORMAT from pre-extracted data>`) specify no labels — LLM infers `**Components**` instead of `**Components used:**` |

---

## Solution

Two code changes to `chunked_prompt.py`:

1. **One-line fix** for tag quotes (Issue #1).
2. **New module-level constant** `_FUNCTION_FORMAT_SPEC` injected into `build_merge_prompt()` (Issues #2 and #3).

`prompt.py` and `pre_synthesis.py` are **not modified**.

---

## Change 1 — Fix tag quote bug

**File:** `chunked_prompt.py`
**Location:** The line inside `build_merge_prompt()` that builds `tags_yaml`.

```python
# Before — produces: tags: ["CLASSIFIED", "ITEMMIMIC"]
tags_yaml = ", ".join(f'"{t}"' for t in presynthesis.tags)

# After — produces: tags: [CLASSIFIED, ITEMMIMIC]
tags_yaml = ", ".join(presynthesis.tags)
```

**Edge case — empty list:** `", ".join([])` returns `""`, which renders as `tags: []` in the YAML template. This is unchanged behavior — correct.

**Edge case — tag content:** DST tag values are simple identifiers (letters, digits, underscores, hyphens) from `inst:AddTag()` / `inst:HasTag()` calls. They never contain spaces, commas, or brackets. YAML flow sequences (`[val1, val2]`) are valid for such values without quoting. This fix is safe under that constraint. If a tag value ever contains a space, it would produce invalid bare YAML — but this cannot happen from the DST codebase.

## Change 2 — Add `_FUNCTION_FORMAT_SPEC` constant

**File:** `chunked_prompt.py`
**Placement:** Module level, after `import json` and `from pre_synthesis import PreSynthesisResult`, before any function definitions.
**Type:** Plain triple-quoted string — NOT an f-string. The constant **must never contain `{` or `}` characters**; this is required because it is interpolated inside `build_merge_prompt()`'s f-string. Verify this invariant whenever updating the constant.

**Bullet style:** `* **Key:**` (asterisk + **one** space). This matches `consolecommands.md` exactly. Note: `prompt.py`'s few-shot example uses `*   ` (three spaces) — this divergence is intentional; the target reference is `consolecommands.md`.

**Tags section style:** The `**Tags:**` sub-section uses one-bullet-per-tag format. This differs from `consolecommands.md` line 72 which comma-joins all tags on one bullet. For large files (e.g., `actions.md` with 150+ tags), per-tag bullets are more readable. The key requirement is the `**Tags:**` label — the sub-format within that section is deliberately more structured than `consolecommands.md`.

```python
_FUNCTION_FORMAT_SPEC = """
=== FUNCTION FORMAT ===
Use EXACTLY this structure for every entry in ## Main functions:

### `FunctionName(params)`
* **Description:** What this function does and when it is called.
* **Parameters:** For a single param: `param` -- type and purpose.
  For multiple params, use sub-bullets:
  - `param1` -- description
  - `param2` -- description
  Write `None` if the function takes no parameters.
* **Returns:** Return value description, or `nil` if nothing is returned.
* **Error states:** Edge cases or early returns. Omit this bullet entirely if none.

=== DEPENDENCY SECTION FORMAT ===
Use EXACTLY these labels in ## Dependencies & tags:

**Components used:**
- `component_name` -- how it is used (methods called, properties accessed)

**Tags:**
- `tag_name` -- add / remove / check

=== FEW-SHOT EXAMPLE ===
Mirror this format only. Do NOT copy the content:

### `ConsoleCommandPlayer()`
* **Description:** Returns the currently selected debug entity, the local player, or the first valid player in AllPlayers.
* **Parameters:** None
* **Returns:** Player instance or `nil` if no valid player found.

### `c_spawn(prefab, count, dontselect)`
* **Description:** Spawns `count` instances of `prefab` at console position. Auto-selects first spawned unless `dontselect`.
* **Parameters:**
  - `prefab` -- string prefab name
  - `count` -- number of instances (default `1`)
  - `dontselect` -- boolean to skip auto-selection
* **Returns:** Last spawned instance, or `nil`.

### `c_save()`
* **Description:** Triggers a save on master sim.
* **Parameters:** None
* **Returns:** None
"""
```

Note: The constant uses `--` (double dash) instead of `—` (em dash) to avoid any encoding issues inside the f-string interpolation. The resulting docs use the character the LLM produces; the format spec itself only needs to be ASCII-safe.

## Change 3 — Inject into `build_merge_prompt()`

Four edits inside the single f-string returned by `build_merge_prompt()`:

### 3a — Update task 5 text

Find this line in the YOUR TASKS block:
```
5. Format `## Main functions` — deduplicate functions by name (prefer longer description), format as ### headings with Description/Parameters/Returns.
```

Replace with:
```
5. Format `## Main functions` using EXACTLY the FUNCTION FORMAT defined in the FORMAT SPECIFICATION section below.
   Deduplicate by function name; prefer the entry with more parameter/return detail.
```

### 3b — Update task 7 text

Find this line in the YOUR TASKS block:
```
7. Write `## Dependencies & tags` — list components and tags from the pre-extracted data.
```

Replace with:
```
7. Format `## Dependencies & tags` using EXACTLY the DEPENDENCY SECTION FORMAT defined in the FORMAT SPECIFICATION section below.
```

### 3c — Update template body placeholder

Find this line in the template body (under `## Dependencies & tags`):
```
<FORMAT from pre-extracted data>
```

Replace with:
```
<FORMAT using EXACTLY the DEPENDENCY SECTION FORMAT from the FORMAT SPECIFICATION below>
```

### 3d — Inject constant before `=== CRITICAL INSTRUCTIONS ===`

Find this exact line (the end of the YOUR TASKS block, before the template body separator):
```
7. Write `## Dependencies & tags` — list components and tags from the pre-extracted data.

---
```

After applying 3b, insert the following immediately before the `---` line that begins the template body:

```
=== FORMAT SPECIFICATION ===
{_FUNCTION_FORMAT_SPEC}
---
```

The `{_FUNCTION_FORMAT_SPEC}` interpolation is valid here because the constant contains no `{` or `}` characters.

## Out of scope

- `prompt.py` — not touched (already correct)
- `pre_synthesis.py` — not touched
- Generated `.md` files — not manually patched; regenerate via pipeline after fix
- `_build_merge_prompt_legacy()` and `build_intermediate_merge_prompt()` — Issues #2 and #3 also affect these functions, but they are not used in the current JSON pipeline. Add a `# TODO(format-consistency): apply _FUNCTION_FORMAT_SPEC here when legacy path is retired` comment above each to track the gap.

---

## Success criteria

Criteria are mechanically verifiable by inspecting the generated output file:

1. YAML `tags:` line contains no `"` character — checked by: `'"' not in line` for the line starting with `tags:`
2. Each function entry in `## Main functions` starts with `` ### ` `` — checked by: each `###` heading line has a backtick as its 5th character
3. Each function body contains `* **Description:**` as a literal string (asterisk + one space)
4. `## Dependencies & tags` section contains `**Components used:**` as a literal string
5. `## Dependencies & tags` section contains `**Tags:**` as a literal string
